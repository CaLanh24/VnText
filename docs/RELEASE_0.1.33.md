# Release 0.1.33 — install-journal safety, OS lock per game, clearer upgrade-patch message

Brain's safety review of 0.1.32 found that four installer safety properties had no test and, on reading the code, real gaps. The Owner (DEV session 2026-11-25) confirmed the release once the gate passes. Task `release-0.1.33`, exact `RELEASE_RUN/candidate-0.1.33`, 8 GiB temporary allocation, 48 MiB reserve, shared 11 GiB, terminal 1 GiB; user data and evidence are preserved. The public 0.1.32 and 0.1.7 baselines (needed for the updater routes) are downloaded under that confirmation.

## Scope
- `install_journal.json` carries a sha256 of its content and is written as temp file → flush to disk → rename (state and receipt writes too). A damaged, truncated, empty or foreign journal is refused with Vietnamese guidance before any game write; game, patch folder and journal stay byte-identical. A 0.1.32 journal (no checksum) is accepted only if every field validates.
- Recovery classifies every journal file against its two known states (before / after the install) before writing anything. A file in neither state (edited by hand, or a backup that does not prove the original) refuses the whole recovery, naming the files and keeping game, backups and journal (a partial recovery would lose backups). A backup torn by a kill while it was copied no longer blocks recovery when its game file was never replaced. Recovery killed at any of its steps converges when run again.
- One VNText writer per game: a named OS mutex keyed by the game folder for install, uninstall and recovery, across the app and standalone installers; Windows releases it when the holder dies. A second writer is refused before reading or writing anything.
- A patch built while another VNText patch was installed, offered to a game that went back to the original: the message now says to build the patch again ("Tạo patch" lại) instead of only "Sai bản game hoặc file nguồn đã thay đổi".
- WPF CSV native-repro fixture: the shared view model let the previous case's preview text pass for the current case, and a Preview overlapping the CSV open's settling was (correctly) reported as changed. The fixture now clears the preview, waits for the editor to settle, and previews again once when told to, as a user would. Product behaviour unchanged.
- Version/provenance 0.1.32 → 0.1.33 and the scoped ordinary transition `release-0.1.32` → `release-0.1.33`.

## Evidence
Receipts in `TEST_RUN/agent-evidence/release-0.1.33/`: installer harness 246 checks — section 16 (damaged journals ×5, recovery killed at every step for every install cut: 96 checks, torn backup, two writers on two threads, hand edits during the interruption), section 17 (two REAL processes: A frozen half way, B refused, A killed, B takes the abandoned lock and recovers to the exact original), section 18 (upgrade patch on a restored game). The new harness run against the 0.1.32 code aborts at the kill-during-recovery section. WPF harness passed 3 of 3 separate runs after the fixture fix.
