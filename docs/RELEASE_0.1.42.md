# Release 0.1.42 — a translated line can no longer stop a Ren'Py game

The Owner reported (chat, 2026-11-28, relayed by Brain) a real crash of a Ren'Py 8.5.2 game patched with 0.1.41: `String '…' ends with an open format operation`, raised by a line of the generated `game/tl/vietnamese/vntext.rpy`. The translated line had a damaged tag/bracket (`[i}`, a stray `{b}{/b}`) and the patch gate let it through. The same report asked for statistics about sentences left in English, a way to report an error of the game itself, and a saved path for the bug package. One release handles all of it. The standing permission of 2026-11-25 applies. Task `release-0.1.42`, exact `RELEASE_RUN/candidate-0.1.42`, 8 GiB temporary allocation, 48 MiB reserve, shared 11 GiB, terminal 1 GiB.

## Root cause
`structural_problems` compared only the `{…}` placeholders and `<…>` tags of the source and of the translation as multisets. Nothing looked at `[` / `]` (Ren'Py interpolation), at brace balance, or at a tag pair that the source does not have, so a line that Ren'Py cannot parse passed every check. Why the machine translation produced `[i}` is **not proven** (see NOT_PROVEN in `AI_STATE.md`); the gap that let it reach the game is closed.

## Changes
- **Ren'Py markup check** (`vntext/renpy_markup.py`): a pure-Python mirror of Ren'Py's interpolation parser and text-tag stack (no SDK needed in the user's app). Used by the patch gate for Ren'Py rows: a line with unbalanced `[ ]`, a changed `[name]` set, a broken `{tag}` stack or an extra empty tag pair is blocked with the plain reason "Dấu [ ] hoặc thẻ { } bị hỏng; game sẽ báo lỗi" and goes to "Cần xem lại". The test fuzzes 4000 strings against the real parser file of the pinned SDK 8.5.3 (`renpy/substitutions.py`) and requires the same verdict.
- **Safe repair before blocking:** `[i}` → `{i}`, stray brackets removed, the tags and placeholders of the source restored. The repaired line is used only if it passes again; otherwise the row is left in English. The count is written to `patch_verification.json` (`repaired_markup_keys`).
- **Post-patch check:** the generated `vntext.rpy` is parsed again line by line before it is written and again after it is written (read-back). A line the game could not display makes the patch FAIL with its line number; the patch is never announced as done.
- **Statistics after "Tạo bản Việt hóa":** `bao_cao_viet_hoa.txt/.json` next to the patch and in the log: sentences patched (and repaired), sentences left in English by reason (untranslated, blocked by the markup check, blocked by another check, game already has another translation, not found in the game file, review-only), and items left out at extraction (technical code, engine-common strings, excluded by the user, built at run time). Only counts and reason words; it is included in the anonymous bug package.
- **"Báo lỗi game"** (Lấy text log page): reads `traceback.txt` of the game, scans the generated translation file, shows in plain Vietnamese what it found (kind of error, which lines of the translation file, which of your translation rows) and, on "Có", builds an anonymous package (kind of exception, Ren'Py version, line numbers, hash of the unit id; no game name, path, or sentence). A second question offers "Gỡ dòng gây lỗi": the faulty blocks are taken out of the game's translation file (a backup is kept beside it) and the game shows the original sentence there.
- **Bug package location:** the message after "Tạo gói báo lỗi" / "Gửi báo lỗi" ends with "Gói cũng được lưu tại <đường dẫn> — bạn có thể đưa đường dẫn này cho người hỗ trợ."; the new button "Mở thư mục chứa gói" opens the folder (both on the log page and on the patch-error panel).
